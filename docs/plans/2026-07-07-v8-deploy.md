## 2. Env vars to set (server `.env`)

All default to today's behavior; set to activate. Starting points from one session/name — tune from distributions, not from WEN alone.

```
STRATEGY_MARGIN_MAX_ENTRY_SPREAD_PCT=0.15      # margin-only tighter entry (WEN was ~0.18 → blocked); cash keeps the shared 0.20. Tighten toward 0.10 with data.
STRATEGY_MARGIN_DIP_TARGET_BOOST_MAX_SPREAD_PCT=0.14   # suppress the dip boost when current spread exceeds this (at/just inside the entry gate)
STRATEGY_MAX_UNDERLYING_CONTRACTS=10           # hard per-name lot ceiling — backstops the compounding multiple (WEN reached 15)
```

Leave off for now (enable from the new logs): `STRATEGY_MIN_OPEN_INTEREST` (affects cash too), `STRATEGY_PHANTOM_QUOTE_GUARD_ENABLED` (watch `phantomQuote:true` detection first), `STRATEGY_MAX_UNDERLYING_NOTIONAL` (contract cap is the primary knob).

## 3. Verify the behavior-changing pieces (first session after deploy)

- **Registry reconcile (#11)** — expect `position-registry-reconcile` log lines; the stale 07-02 `MARA`/`CLSK` OPEN entries should self-heal on the first cycle. Confirm **no legitimately-open cash overnight hold** was pruned. This is the one to watch closely — it feeds overnight/sizing/seeding, and it fixes the re-entry-churn bug.
- **Day-report (#12)** — `data/day-reports/*.ndjson` should get a **fresh row at ~12:55 PT** (no longer frozen). If still stale, the 12:55 gate isn't being reached.
- **Dip boost (#3)** — `dipTargetBoostPct` should now be able to fire when a group is down on the **mid** with booleans ≥4 (it was ask-blind all Monday). With the suppression var set, wide-spread names are excluded.
- **Liquidity gate (#1/#2)** — with the margin entry-spread var set, `liquidity-gate` log lines should show margin **blocking** wide-spread names while cash still passes them. Unknown OI/size must **pass + log** (never treated as zero).
- **Underlying cap (#4)** — `allocation-underlying-cap` log when an add is clamped/skipped at the ceiling.
- **Notify breadcrumb (#8)** — `grep '\[notify\]'` in the pm2 out log shows each emit locally (`sent` / `no-socket`). This is independent of the secret socket, so it verifies notifications fired even while the secret-server side is still being debugged.
- **Streamer session (#6/#7)** — on a graceful restart the dxLink session should close cleanly; watch whether the `UNAUTHORIZED: user sessions exceeded limit` restarts drop.
- **Overnight snapshot (v6 #12)** — after the first morning cycle (6:30–10:00 AM PT), `data/overnight/*.ndjson` should get one row per account; `grep '"scope":"overnight-snapshot"'` in the out log. `pairedWithPriorClose:true` only once a prior day-report close exists — so full overnight P&L first lands the morning *after* the first 12:55 day-report writes (chicken-and-egg on day one is expected).
